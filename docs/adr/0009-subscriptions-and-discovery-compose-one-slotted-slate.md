# Subscriptions and discovery compose one slotted daily slate

The daily discovery run gated: person-sourced material was the primary signal and interest search was a gap-filler *skipped entirely* once person supply met a threshold (issue #149, lineage of [[0008-discovery-inputs-trace-to-a-human-act]]). The observed failure: on a subscription-heavy morning (an adult with 35 person-sourced items) interest search was skipped wholesale, so the slate carried **zero discovery** — no exploration on exactly the days the household is most engaged. Separately, new uploads from followed people never reached the **Candidate pool** at all: the RSS poller wrote them straight to `requests` (the download path) and they surfaced in a separate "From people you follow" feed band, so they never competed on score, never went through the guard for kids, and could not participate in slate composition.

The rule: **the daily slate is one scored, capped pool composed into reserved slots — subscription-led, with hard floors for back-catalog and delighters. The cap is a ceiling, not a target. The only kid/adult difference is the guard.**

## Consequences

- **Subscriptions become scored candidates.** New follow uploads enter `candidate_pool` as `source_type = 'subscription'`, run through the same scoring → guard → surfacing pipeline as everything else, and are downloaded only if they win a slot (like any **Pick**). The RSS poller stops creating `requests` directly and creates candidates instead; shorts-filtering and `seen_videos` dedup stay. **Following is no longer a guaranteed bypass** — a followed creator's new upload can be guard-rejected for a kid. That is the correct safety posture (kid-safety non-negotiable; locked prior-session decision that follows run through Gemma with the same floors as picks).
- **A slot allocator replaces the #149 gate.** Three buckets compose the slate: *subscription* / *back-catalog* / *delighter* (= declared-interest `interest_search`). Two hard floors — **back-catalog 4, delighter 2** (role-blind, absolute) — are reserved every day, even on a flood day. Subscriptions fill the remainder up to the per-user cap (`cap − 6`). Spare capacity is **not** soaked into back-catalog: a thin-supply day yields a genuinely short slate, which is a valid state per **Scarcity**.
- **Numbers are role-blind; the guard is the only kid/adult difference.** Slate size is a per-user `daily_pick_cap` column on `users`, defaulting to a global `.env` value (15 to start). Diversity caps unify to **3 per interest, 2 per channel** for everyone. The per-channel cap and title dedup apply globally (including subscriptions); the per-interest cap applies to back-catalog and delighters but **not** to subscriptions — following a person is an explicit choice that an inferred-interest grouping must not suppress. The kid guard recheck is unchanged.
- **Follows keep rankWeight 1.0** (locked prior session). The slate orders by weighted score (`connection × quality × freshness × rankWeight`); the freshness multiplier (1.6× for <24h) already floats new uploads to the top, so there is no separate recency sort for the subscription bucket.
- **The daily run polls subscriptions first.** The discovery job triggers an RSS poll as its first step (awaited), then composes — retiring the drift-prone 6-hour `setInterval` poller whose phase was re-anchored on every server restart. Because subscriptions are now *candidates* (not downloads), they count the moment they are polled; there is no download-completion lag in the composition decision.
- **Provenance stays three-valued: *request* / *follow* / *pick*.** *Follow* covers both subscription and back-catalog cards (anything from a **Person** you follow); *pick* is the **Delighter** (discovery beyond your follows). The unified slate mixes provenances in one composed set rather than separate bands.

## Considered and rejected

- **Keep the gate** (skip discovery when person supply is sufficient). Rejected: it starves exploration on the household's most active days — the observed failure that motivated this.
- **Subscriptions keep a privileged direct-to-feed path** that skips scoring and the guard. Rejected: it breaks slate composition and, for kids, skips the guard — a safety hole.
- **Kid/adult numeric asymmetry** (the prior 5-vs-15 size split and tighter 1-per-interest/channel kid caps). Rejected: Scarcity and breadth are household-wide values, not kid throttles. Kids are not a throttled adult feed — they are an adult feed *plus the guard*.
- **Soak spare slots with back-catalog to always fill the cap.** Rejected: it violates **Scarcity** ("finishing Today is a valid state"). A short slate is the correct output when supply is genuinely thin.

## Deferred

- **Cold-start delighter expansion** — when a user has *no* follow supply at all (no subscriptions and no back-catalog), let the delighter bucket expand to fill the cap so a brand-new user is not handed a 2-item slate. Deferred because the live users all have follows; this can be patched manually for them. Note the existing cold-start regression test (`feed.coldstart.test.ts`, #164) encodes the current "no person-sourced → full interest search" behaviour and will need revisiting when this lands.
- **Per-user daily appetite** beyond a single column default — e.g. different caps for differently-aged kids — rather than one default for the whole household.
- **A genuine serendipity signal** for the delighter slot. Today the slot is filled by declared-**Interest** search, which is on-topic, not truly surprising; "delighter" names the slot's *purpose* and a real serendipity source is a separate, later issue.
- **Today UI collapse** (three stretches → two: *You asked* + a unified *Today*), the death of "picks always render as hero", and provenance-pill adequacy. Frontend; the proposed direction is recorded here but is confirmed when that slice is built, not by this ADR.
